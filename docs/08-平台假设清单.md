# 平台假设清单（Windows 已实测 / Unix 未验证）

> 2026-10-18。目的：把「代码里依赖平台行为的地方」列清楚，**不靠读代码猜平台语义**。
> 三个结论必须分开：
> 1. **代码看起来跨平台**（有分支、有归一化）；
> 2. **测试在某个平台实际通过**（真跑过）；
> 3. **项目承诺在该平台受支持**（写进 README/承诺表）。
>
> 当前：**Windows = 1 + 2 + 3**；**Unix = 只有 1**（静态），没有 2，也不承诺 3。

## 二、哪些现在能做、哪些等环境

### 现在做（本清单本身就是）
- 列出全部平台假设 + 三态标注；
- 确认 CI 配置与探针退出状态设计（FAIL 红；BLOCKED/NOT_TESTED 不红——**不预加豁免**）；
- 确认"看起来跨平台"与"承诺支持"的区别写进 README/03 表。

### 以后做（拿到真实 Ubuntu 结果后）
- 大小写敏感文件系统：`/home/A/x` 与 `/home/a/x` 必须是两个文件；
- Unix 锁：陈旧锁接管是否可能双持；
- 时间戳/权限差异：Move 后 mtime/owner 行为；
- 探针在 ubuntu 上的实际状态（BLOCKED 可能变 PASS——**按实际结果区分平台差异与代码缺陷**）。

## 三、结论

- **Windows**：代码具备 + 实测通过 + 承诺支持（有证据）；
- **Unix**：代码具备（有分支）+ **未实测** + **不承诺**（README §6 明确写"Unix 未验证"）；
- **CI**：配置存在 ≠ 运行通过（本目录无远程仓库，从未触发过 CI）。
