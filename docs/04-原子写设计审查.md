## 1. 四项兼容性评估

### 1.1 mtime 语义（改变 = 高风险）

**当前行为**（`WriteAllText` 直接写目标）：写入后 mtime = 写入时间。调用方与外部工具（`git status` / `rsync` / `make` / `inotify`）都依赖它判断"文件变了"。

**原子写候选**：写 `<目标>.tmp` → `File.Move(overwrite)`。`rename` 会重置 inode/属主，mtime 是否保留取决于是否显式拷贝（探针场景 2 证明"能拷"）。

**关键判断**：
- **保留旧 mtime 在语义上是错的**：文件内容变了却告诉外部"没变"，会让版本控制/同步工具漏掉改动。
- 保留旧 mtime 只对"只想改内容、不想触发下游"的调用方有利——但这应该由调用方**显式选择**，不能是默认。
- ⇒ 推荐：**默认不拷 mtime**（保持"写后 mtime 更新"，与现状一致）；若未来提供，做成显式开关并写入文档。

**必须回答的问题**：
- 现有 `Prune-Backups` 的 `-OlderThanDays` 用**备份文件**的 mtime（不受影响），但目标文件的 mtime 变化会不会被别的自动化依赖？
- `-Verify` 读回核对是否依赖 mtime？（不依赖，依赖字节/SHA256。）

### 1.2 备份语义（改变 = 中风险）

**当前行为**：写前 `Backup-WgSnapshot` 按原始字节备份（`<原名>@<hash8>.bak-<时间戳>`），再写目标。

**原子写后**：
- 备份仍是**写前字节**，语义不变（`Restore-WgSnapshot` 可用）。
- 新增 `<目标>.tmp` 生命周期：
  - 成功：Move 后 tmp 不存在（探针场景 2 验证 `tmpLeftover=False`）；
  - 失败：**必须主动清理 tmp**，否则目录被污染；
  - 进程中断：tmp 残留（探针场景 4 已验证"目标原样 + tmp 残留"）。
- `Prune-Backups` 按 `*.bak-*` 匹配 ⇒ **不会**误删 tmp；但 tmp 会占空间。
- ⚠️ 不能自动删除"别人"的 tmp：清理必须限定为**本进程命名规则 + 自己创建**的文件，且失败路径优先于清理。

**必须回答的问题**：
- tmp 命名是否唯一（避免两个 WriteGuard 进程撞名）？命名规则需与锁、备份、清理三方都不冲突。
- 中断残留的 tmp 要不要提供显式清理命令（只按命名+时间，不猜）？

### 1.3 锁的交互（改变 = 中风险）

**当前行为**：`-Lock` 在 Commit 时对目标建 `<目标>.wglock`（`FileShare.None`），覆盖**整个写入事务**（快照 → 写 → 读回），`finally` 释放。

**原子写后**：
- 锁仍应覆盖**整个事务**（含 tmp 写入与 Move），不是只保护某一步；否则两个 WriteGuard 进程可能各写各的 tmp 再互相覆盖。
- **对外部读者**（不遵守锁的进程）：rename 原子性提供"只看到旧或新"（探针场景 5 的观察，2 秒采样窗口）。
- 锁文件与 tmp 文件必须**分得清**：`*.wglock` / `*.tmp` 命名不重叠；清理逻辑只碰自己那一类。
- 风险：非 WriteGuard 进程若按"文件名 + 时间"扫描目录，可能把 tmp 当成目标文件——需要文档与命名规避。

**必须回答的问题**：
- 锁是"按目标文件"还是"按目录"？（现状按目标文件；tmp 是否也要加锁？）
- 其他 WriteGuard 进程在锁被占时是 `Refused`（现状）——原子写下这个语义不变吗？

### 1.4 失败与恢复（改变 = 高风险）

**当前行为**：写入异常 → 统一事务保护 → 按备份回滚；回滚前核对"是不是我写的"（`RollbackRefused`）。

**原子写后，失败点变多**：

| 失败点 | 目标文件 | 临时文件 | 回滚需要？ |
|---|---|---|---|
| tmp 写入失败 | 原样 | 可能残留/半截 | 不需要（目标未动），清理 tmp |
| Move 失败（权限/只读/路径） | 原样 | 残留 | 不需要，清理 tmp；记录异常（**不归因 OS**） |
| Move 成功、读回复验失败 | 已是新内容 | 无 | **需要**，按备份回滚（现有逻辑） |
| 进程中断（Move 前） | 原样 | 残留（可识别） | 不需要；提供显式清理，不自动删 |
| 进程中断（Move 瞬间） | 理论原子（**未证明**） | — | **NOT-PROVEN**，不能说"一定完整" |

**必须回答的问题**：
- 状态机是否需要新状态（如 `MoveFailed`）？还是复用 `Error` + `Note`？（加状态要同步 `Get-WgStatusTable`，否则 ㊲ 会炸——这是好事。）
- 回滚失败时，tmp 与备份的清理顺序？不能先删备份再回滚。

## 2. 证据等级（与探针对齐）

| 项 | 等级 | 说明 |
|---|---|---|
| File.Replace 本机不可用 | **BLOCKED**（环境） | Access denied，异常已记录；不是"原子写失败" |
| File.Move(overwrite) 可用 + 时间可拷 | **PASS**（当前环境） | 临时目录、同卷、200 次替换 |
| Move 前中断目标原样 | **PASS**（模拟） | 不是真杀进程 |
| 并发读者只看到完整旧/新 | **PASS**（2 秒采样） | 样本窗口有限，不外推 |
| **Move 瞬间断电/被杀** | **NOT-PROVEN / NOT_TESTED** | 唯一真正的崩溃安全命题，**没有运行** |
| 非受限 Windows / Unix 真实文件系统 | **NOT-VERIFIED** | 补测条件：VM 快照/断电注入 + 非受限 Windows；Unix 需真实文件系统 |

> 结论的写法必须带条件：**"在 Windows 10（当前环境）+ 临时目录同卷 + 200 次替换窗口内，未见半截"**，
> 而不是"原子写是安全的"。

## 3. 若要进入主路径：前置条件清单

1. **mtime 决策**：默认不拷（保持更新），还是显式开关？（建议：默认不拷 + 文档写明）
2. **tmp 契约**：命名规则、失败清理、中断残留识别、显式清理命令（不猜不自动删）
3. **锁覆盖**：整个事务（含 tmp）在锁内；命名与 `*.wglock` 不冲突
4. **状态机**：新增状态要进 `Get-WgStatusTable`（㊲ 契约测试会强制）
5. **回滚顺序**：备份 → 目标 → tmp 的清理顺序；回滚失败时不得删备份
6. **证据边界**：README 与 03 表只能写"已验证的部分"，崩溃安全保持 NOT-PROVEN
7. **对照实验**：非受限 Windows 上重跑探针；若有 VM，做断电注入（限定环境与故障模型）

**在这些问题回答之前，不改 `Invoke-WgWrite` 的主路径。**
