# WriteGuard —— 「写操作五规矩」的可复用护栏（PowerShell 7+）

> **一句话**：脚本要**替人改文件**时，把「精确改、先备份、写后验、失败能回滚、状态可核验」交给它，别在每个开关里手写一遍。
> **给谁用**：**写自动化修复脚本的人** —— 批量回填、检查器自修、知识库维护，那些"改完之后还得知道到底改对没有"的场合。
> **不解决什么**：它不是沙箱、不是文件系统级原子提交、不是版本控制，也不替你做审批（那是宿主的事）。
> **依赖**：**只有 PowerShell 7 + .NET 原生** —— 不依赖 DSH、不依赖任何第三方模块、无网络、无外部命令
> （只有跑测试时要 `pwsh` 自己）⇒ **装在 pwsh 7 的 Windows / Linux / macOS 上都能用**。DSH 只是它的出生地，不是它的门槛。
> **状态**：**v0.1.6（2026-10-18）** · 自测 **58/58** · 元验证 **31/31** · CLI **5/5** · 真实数据接线已验证（见 §5.4）。
> **第一次来？** 跑 `pwsh -NoProfile -File .\Start-Here.ps1` —— 它会把五套测试跑一遍，并列出"还剩什么没做"。
> 认领清单在 [ROADMAP.md](ROADMAP.md)（含每条任务的**判据**），接手须知在 [接手说明.md](接手说明.md)。
> 版本变更（v0.1.1 → v0.1.6）见 [CHANGELOG.md](CHANGELOG.md)；**边界、环境与支持范围**见 §6。

## 0. 五条规矩

| # | 规矩 | 一句话判据 | 库里的落点 |
|---|---|---|---|
| ① | **默认不开** | 不显式授权 ⇒ 一个字节都不写 | `Invoke-WgWrite` 必须传 `-Commit`，否则 `DryRun` |
| ② | **原样备份** | 写盘**之前**按**原始字节**备份，写完读回核对哈希 | `Backup-WgSnapshot`（内部：写备份 → 读回比 SHA256） |
| ③ | **只改白名单** | 唯一匹配才改；0 处或多处匹配一律**拒绝**（不猜） | `Set-WgUniqueSpan` / `Set-WgJsonScalar` / `Assert-WgUniqueMatch` / `Resolve-WgSingleTarget` / `Select-WgUniqueLatest` + `-MaxChangedLines` |
| ④ | **读回复验** | 写完**重新读磁盘**比对文本 + BOM，再跑调用方的断言 | `Invoke-WgWrite -Verify`（复验**抛异常也算失败**） |
| ⑤ | **失败回滚** | 复验不过 ⇒ 按备份字节还原；**但回滚前先核对"现在这份是不是我写的"**，是别人改的就拒绝覆盖 | `Restore-WgSnapshot` + 状态 `RolledBack` / `RollbackRefused` / `RollbackFailed` |

外加两条血换来的：
- **"没算出来" ≠ "没问题"**：**复验脚本**抛异常一律当**失败**（会触发回滚）；**读**审计日志遇到坏行**直接抛**（不许静默跳过）。
  ⚠️ 但**写**审计日志失败**不改变**主操作结果（只记 `$r.AuditError`）—— 这三件事别混（见特色 2；"强制审计模式"见 ROADMAP G 项）。
- **算差异 / 做清理的循环必须能报出失败**：库内一律 `try/catch` + 结构化结果，绝不"看着像执行了"。

## 0.5 灵魂：注入

> **"检查通过" ≠ "检查有效"。你没见过它报红，就不知道它会不会报红** ——
> 一个永远全绿的检查器，和没有检查器，在出事那天是一样的。

所以本库不满足于"跑通"：**它给自己注入故障** —— 把每条规矩**故意改坏**（改在副本上），
看自测会不会抓到、抓到的**是不是期望的那一条**。现在**每个注入场景都被抓到**（确切条数见 §5.2）；
而那套骨架已经**通用化**（`tests\FaultInject.ps1`：目标 / 场景 / 断言全走参数），**别人的检查器也能用**。
细节与证据见 §5.2 / §5.3。
> 📖 **完整方法论**：[检查器自证清单.md](检查器自证清单.md) —— 12 条，每条「判据 / 最小做法 / 反例」，
> 不指向任何私有文件；配一套**能跑的最小示例** `examples\minimal-checker\`（40 行检查器 + 3 场景 + 一键脚本）。

## 1. 五个特色（别人来看的就是这些）

### 特色 1 · **看得见**：每次改动都给 diff 预览

不传 `-Commit` 也照样把"会改成什么样"打出来（带 3 行上下文、行号、`-`/`+`），所以**没有盲写**这回事。

```powershell
$r = Invoke-WgWrite -Path .\config.json -Mutator { param($s) Set-WgJsonScalar -Text $s.Text -Field 'version' -Value '2.1.0' }
$r.DiffText      # ← 就是它；DryRun 时也有
```

实测（179 行真实 JSON）：

```
@ 基线.json
    172 |     "提示词库条数": "| 提示词库 | **32 类 / 5989 条** | ...
    173 |     "OpenRouter 到期日": "| **OpenRouter Key** | **2026-11-01 到期** | ...
    174 |   },
-   175 |   "rulesVersion": "v4.5",
+   175 |   "rulesVersion": "v9.9-test",
    176 |   "authRowsSig": "视频时长 · 日常档=时长 · 日常档|...
```

### 特色 2 · **可追溯**：每次写操作都能留审计

`-Audit`（默认落目标文件同目录 `.writeguard\audit.jsonl`）或 `-AuditLog <路径>`，每次操作记一行 JSON：
时间 · 状态 · 文件 · **写前 SHA256** · 改动行 · 行差 · 备份路径 · 复验问题 · 备注。用 `Get-WgAudit` 读回来。

```powershell
Invoke-WgWrite -Path .\config.json -Commit -Audit -Mutator { ... }
Get-WgAudit -Path .\.writeguard\audit.jsonl -Tail 20
```

⚠️ 审计**默认不开** —— 保持"不传 `-Commit` 就一个字节都不动"的干净语义；
审计日志写失败**不改变**主操作结果，但会记进 `$r.AuditError`（**失败要报出来**，不静默）。
⚠️ 日志坏了一行 ⇒ `Get-WgAudit` **直接抛**，不跳过那一行（"没算出来" ≠ "没问题"）。

### 特色 3 · **多文件原子**：要么全成，要么全退

一次改多个文件时，怕"改到一半失败"是最现实的恐惧。`Invoke-WgBatch` 分两段：
**先全部演练**（一个字节都不写，任一项不能安全执行 ⇒ **整批拒绝**），**再逐项真写**（任一失败 ⇒ **把本次已写的全部按备份字节回滚** —— 除非其中某一份在回滚前**已被第三方改动**，此时**拒绝覆盖**并报 `RollbackRefused`）。

⚠️ **"原子"的准确范围（别读大）**：它保证的是**可处理失败时的整批回退**。
**进程被杀 / 断电 / 回滚本身失败**时**没有**崩溃恢复协议（那需要持久化事务日志 + 恢复流程，本库不做，见 §6 边界）。
回滚凭据绑定的是**本次提交前**的字节，**不是**演练阶段那份 —— 若某项在**演练之后**被改过，
结果里的 `DriftedPlans` 与 `Note` 会告诉你"演练预览对它已过时"（外部审计 2026-10-17 问题 A）。

```powershell
Invoke-WgBatch -Commit -Plan @(
  @{ Path = '.\a.md'; Mutator = { param($s) Set-WgUniqueSpan -Text $s.Text -Pattern '旧' -Replacement '新' -What '标题' } },
  @{ Path = '.\b.md'; Mutator = { param($s) Set-WgUniqueSpan -Text $s.Text -Pattern '甲' -Replacement '乙' -What '正文' } }
)
# BatchStatus：Committed · AllDryRun · NoChange · Refused · RolledBack · RollbackRefused · RollbackFailed · Error
```

### 特色 4 · **元验证（灵魂）**：证明"自测不是装饰品"

`tests\MutationCheck.ps1` 把库按某条规矩**故意改坏**（改在副本上），自测**必须报红、且必须是期望的那一条**。
现在是 **每个注入场景都被抓到，外加 1 个噪声场景确认"尺子不过敏"** —— 一条规矩如果"改坏了也没人发现"，那条自测就是假的。

### 特色 5 · **不改代码就能用**：命令行门面 `wg.ps1`

```powershell
pwsh -NoProfile -File .\wg.ps1 json    -File .\config.json -Field version -Value 2.1.0        # 演练（看预览）
pwsh -NoProfile -File .\wg.ps1 json    -File .\config.json -Field version -Value 2.1.0 -Commit -Audit
pwsh -NoProfile -File .\wg.ps1 replace -File .\doc.md -Pattern '旧的标题' -Replacement '新的标题' -Commit
pwsh -NoProfile -File .\wg.ps1 check   -File .\doc.md -Pattern '^## 一、'                        # 只查唯一性
pwsh -NoProfile -File .\wg.ps1 audit   -File .\.writeguard\audit.jsonl -Tail 20
```

## 2. 来历（为什么是我们写这个）

本机一个 1100 行的知识库体检脚本里有 **5 个"显式授权才写"的开关**（`-FixAuthTable` / `-FixRuleSig` /
`-WriteHandoff41` / `-FixLatestHandoff` / `-PruneExempt`），**同一套规矩各写了一遍**（备份目录都分了五个）。
规矩不是想出来的，是踩出来的：

- **三次"看着执行了、其实什么都没做"** —— `$ErrorActionPreference='Continue'` 把越界 / 属性不存在的异常静默吞掉。
- **一次"改一处、动全文件"的风险** —— 整份 `ConvertTo-Json` 重写会重排键序 / 改缩进 / 动转义。
- **一次"测试脚本自己撒谎"** —— 变量名大小写互相覆盖、传了未声明的参数被吞进 `$args`。

## 3. 快速开始

### 3.0 三件套：先看、再试、最后才动手

改文件之前，每一步都可以停下来。三档按"危险度"递进：

| 档 | 怎么用 | 会改文件吗 | 什么时候用 |
|---|---|---|---|
| **① 只读检查** | `wg check -File <路径> -Pattern <正则>` | ❌ 只读 | 先确认"目标唯一吗"—— 0 处或多处都直接拒绝，不猜 |
| **② 预演** | 任何写入**不传 `-Commit`** | ❌ 一个字节不动 | 看 diff 预览、改动行数、会不会越 `-MaxChangedLines` |
| **③ 确认** | 传 `-Commit` | ✅ 有备份、有复验、失败回滚 | 看过 ①② 之后才用 |

**失败时怎么退**：看 `$r.Status`——
`Written` 是成了 · `Refused` 是**没动**（最安全）· `RolledBack` 是写了又还原 ·
`RollbackFailed` 是要你拿 `$r.Backup` 手工救。完整语义见 §4。

> 三条原则：**默认动作是不动**（不传 `-Commit` 什么都不发生）·
> **拒绝比猜好**（目标不唯一就停）· **失败要报真话**（回滚失败绝不写成"已回滚"）。

### 3.1 当库用

```powershell
Import-Module .\WriteGuard.psm1

# ① 演练：不传 -Commit ⇒ 只看会改什么
$r = Invoke-WgWrite -Path .\config.json -Tag 'bump' -MaxChangedLines 3 -Mutator {
        param($s)
        Set-WgJsonScalar -Text $s.Text -Field 'version' -Value '2.1.0'
      }
$r.Status        # DryRun
$r.DiffText      # 预览

# ② 真写：备份 → 写 → 读回复验 → 不过就回滚
$r = Invoke-WgWrite -Path .\config.json -Commit -Tag 'bump' -Audit -MaxChangedLines 3 `
     -Mutator { param($s) Set-WgJsonScalar -Text $s.Text -Field 'version' -Value '2.1.0' } `
     -Verify  { param($text, $path) $issues = @(); if (-not $text.Contains('"version": "2.1.0"')) { $issues += '版本没写进去' }; $issues }
"$($r.Status)：$($r.Note)   备份：$($r.Backup)"
```

## 4. API 速查

| 函数 | 干什么 |
|---|---|
| `Invoke-WgWrite -Path -Mutator [-Verify] [-Commit] [-Tag] [-BackupDir] [-MaxChangedLines] [-MaxDiffLines] [-Audit] [-AuditLog] [-Encoding]` | **主入口**：一次受护栏保护的改写（内核 + 审计） |
| `Invoke-WgBatch -Plan [-Commit] [...]` | **多文件事务**：全成或全退 |
| `Get-WgSnapshot -Path` | 读快照：原始字节 / BOM / 换行风格 / 文本 / SHA256 |
| `Backup-WgSnapshot -Snapshot [-BackupDir] [-Tag]` | 按原始字节备份（默认落同目录 `.writeguard\`），写完读回核对 |
| `Restore-WgSnapshot -Snapshot` | 按备份字节还原（原文件本不存在的快照 ⇒ 拒绝，避免误删） |
| `Get-WgDiffText -Old -New [-Context 3] [-Header]` | 生成改动预览（剥公共前后缀 ⇒ 只显示真正变的那段） |
| `Set-WgUniqueSpan -Text -Pattern -Replacement [-ReplacementScript]` | **唯一匹配才替换** |
| `Set-WgJsonScalar -Text -Field -Value [-InsertAfter] [-AsNumber]` | 只改 JSON 里**那一行**（缺字段时须给锚点） |
| `Assert-WgUniqueMatch -Text -Pattern [-What]` | 0 处 / 多处匹配都抛（"不猜"） |
| `Resolve-WgSingleTarget -Candidates` | 目标必须唯一：0 个或多个候选都抛 |
| `Select-WgUniqueLatest -Candidates -KeyScript` | 按 key 取最新（如**文件名里的时间戳**，不用 mtime） |
| `Get-WgAudit -Path [-Tail 20]` | 读审计日志（JSONL）→ 对象数组；坏行直接抛 |
| `Get-WgInfo` | 版本 + 五规矩（供自证清单 / 交接件引用） |
| `Get-WgStatusTable` | **状态语义表（机器可读的单一事实源）**：`Status · Kind · ExitCode · Meaning` |
| `Get-WgExitCode -Status` | 状态 ⇒ 进程退出码（CLI 与它共用同一张表；未知状态**抛异常**，不猜） |

**`Mutator` 契约**：`param($snap)`，用 `$snap.Text` / `$snap.NewLine` 算新文本；返回
`字符串` 或 `@{Text=...;Note=...}`；返回 **`$null` = 主动放弃**（定位不到就放弃，别猜）；抛异常 = 拒绝。

**`Verify` 契约**：`param($textAfter, $path)`，返回问题清单（空 / `$null` = 通过）；**抛异常一律算失败**。

### 结果状态

> ⚠️ 下面这张表是**给人读的**；机器读的**单一事实源**是 `Get-WgStatusTable`
> （`Status · Kind · ExitCode · Meaning`），命令行门面的退出码走 `Get-WgExitCode`。
> **加了状态却忘了进表，自测 ㊲ 会当场报红** —— 不再靠"记得同步"。

| Status | 含义 | 文件动了吗 | 退出码 |
|---|---|---|---|
| `Written` | 已写 + 读回复验一致 + 有备份 | ✅ 动了（有备份） | 0 |
| `NoChange` | 新内容与现状一致 ⇒ 不写、不备份（**幂等**） | ❌ | 0 |
| `DryRun` | 没传 `-Commit`（演练） | ❌ | 0 |
| `Refused` | 主动拒绝：文件不存在 / Mutator 放弃 / 不唯一 / 超 `-MaxChangedLines` / 写前哈希复核不一致 | ❌ | 1 |
| `RolledBack` | 写了但复验不过 ⇒ **已按备份字节回滚** | ❌ 已还原 | 1 |
| `RollbackRefused` | 回滚前发现目标**已被第三方改动** ⇒ **拒绝回滚**（拿旧备份覆盖会毁掉更新的数据） | ⚠️ 保持现状，请人工处置 | 1 |
| `RollbackFailed` | 复验不过**且回滚失败** ⇒ 请手工用 `$r.Backup` 还原 | ⚠️ 中间态 | 1 |
| `AuditBlocked` | 传了 `-StrictAudit`、但审计记录写不进去 ⇒ **写入作废，已按备份还原**（默认模式不会出现） | ❌ 已还原 | 1 |
| `Error` | 未预期错误（Mutator 抛异常、IO 失败、写入未生效等） | ❌ 一般没动 | 1 |

（批量另有 `BatchStatus`：`Committed` · `AllDryRun` · `NoChange` · `Refused` · `RolledBack` · `RollbackRefused` · `RollbackFailed` · `Error`）

> **`-StrictAudit`（严格审计）**：默认是"审计写不进去只记 `AuditError`，主操作照常成功"——审计是旁路，
> 不该让写操作失败。但正式入库可以要求"**没有审计就不算写成**"：传 `-StrictAudit` ⇒ 审计记录写不进去时，
> **这次写入作废、按本次提交的备份还原**（状态 `AuditBlocked`，退出码 1）。
> 回滚前照样核对"现在这份是不是我写的"，被第三方改过就 `RollbackRefused`。
> ✅ **批量路径已接入**（2026-10-17 补）：`Invoke-WgBatch` 把 `-StrictAudit` / `-Lock` 透传给每一项，
> 语义沿用"**一项失败 ⇒ 整批回退**"。证据：自测 **㊿e1 / ㊿e2** · 元验证 **M23a / M23b**。

### 5.1 自测 58/58 —— 主打**反向验证**（`tests\SelfTest.ps1`，零依赖，不用 Pester）

pwsh -NoProfile -File .\tests\SelfTest.ps1

覆盖：BOM / 换行判定 · 默认不开（不写、不备份、**不建目录**）· 备份与写前**逐字节一致** ·

**diff 预览只含真正变的那段** · **审计落盘 + 不开审计不多一个文件** · **审计失败要报出来** ·
**批量：演练 / 整批拒绝 / 失败回滚已写文件 / 全成 / 幂等** · **审计坏行必须抛** ·

**写后哈希 == 磁盘现状**（㊱）· **状态语义表契约：源码里出现过的状态必须都进表**（㊲）·
**审计记录含 opId / 写后哈希 / 恢复状态**（㊴）· **批量回滚回到「本次提交前」而不是演练旧快照**（㊵）·
**只改大小写也必须真写、diff 也要看得见**（㊶ / ㊷ —— 使用者发现的 `-eq` 不区分大小写那个坑）。

### 5.2 元验证 31/31 —— **给自测本身做故障注入**（`tests\MutationCheck.ps1`）

```
pwsh -NoProfile -File .\tests\MutationCheck.ps1
```

> 这套做法已经抽成**通用骨架** [`tests\FaultInject.ps1`](tests/FaultInject.ps1)：目标 / 场景 / 断言 / 场景参数全走参数；

### 5.3 开发中**被抓到的四个真 bug**（这才是测试的意义）

1. **JSON 插入新字段漏尾逗号** ⇒ 会插出非法 JSON（元验证抓到）。
2. **`$x = if (...) { @($arr[a..b]) } else { @() }`** ⇒ `if` 的输出流把**单元素数组展开成标量**，
   StrictMode 下 `$x.Count` 当场报错（自测的 diff 预览那条抓到）。
   与"pipeline 展开嵌套数组"是**同一族坑** —— 遍历 / 承接数组一律显式建 `ArrayList`。
3. **`ChangedLines` 与 diff 预览口径不一致** ⇒ 插入 2 行报"改动 4 行"，被 `-MaxChangedLines` 误判成越界
   （做 ROADMAP-A「示例解绑」时被判据逼出来的）。⇒ 修法是让两者都**先剥公共前后缀**。
4. **`-eq` 对字符串不区分大小写** ⇒「只改大小写」被判成"内容没变"：报 `NoChange`、**修改被静默丢弃**，
   diff 还会把这类行当成"没变"（预览与实际写入不一致）。
   ——— **2026-10-17 由使用者发现**（不是审计提的，也不是自测抓的：前两者都没想到这一层）。
   复现极简：`'Hello World'` → `'hello world'`，旧版报 `NoChange`、文件一字未动。
   ⇒ 修法：**所有文本内容比较改用 `-ceq` / `-cne`**（哈希 / 状态 / 计数 / 字节那类是自产常量，不受影响、保持 `-eq`）；
   连测试里的 `Assert-Eq` 也改成大小写敏感 —— **尺子自己不敏感，就会替被测对象漏报**。
   证据：自测 **㊶ / ㊷** + 元验证 **M12 / M13**（把 `-ceq` 改回 `-eq` ⇒ 那两条必须报红）。

## 6. 取舍与边界（诚实清单，别当它是牢笼）

- **运行环境与支持范围（v0.1.6）**：
  - **平台**：Windows + PowerShell 7（本机 7.6.6 实测）。Unix 的锁接管语义 / 真实文件系统大小写语义**未验证**。
  - **控制台编码**：测试**不依赖**宿主默认代码页（cp65001 / cp936 / cp437 三档实测全绿）。
    ⚠️ 但 CLI 输出是中文：代码页显示不了中文时（如 cp437），**显示**会变成 `?` ——
    这是显示层限制，**不影响退出码和文件字节**。工具定位是中文社区，国际化留到 JSON / 状态码接口。
  - **编码支持**：UTF-8（有/无 BOM）/ gb2312 / gb18030；UTF-16 检测到 BOM 直接拒绝。
    字节保真的承诺范围 = 库支持的编码（㊿f），**不是任意编码**。
- **只处理文本**。二进制请直接用 `Backup-WgSnapshot` + `Restore-WgSnapshot`。
- **字符串比较是大小写敏感的**（`-ceq` / `-cne`）：这是 v0.1.4 的修复 —— PowerShell 的 `-eq` 对字符串
  **不区分大小写**，而本库要判断"内容到底变没变" ⇒ 用 `-eq` 会把"只改大小写"判成"没变"。
  ⚠️ 你自己写 `-Mutator` / `-Verify` 时**同一个坑照样在**：判内容用 `-ceq` / `-cne`，正则用 `-cmatch` / `-creplace`。
- **`ChangedLines` / diff 是保守算法**（**先剥公共前后缀，再对中间段做同索引比较**；行号按**改动前**的坐标）：
  **不会漏报，但中间段内可能多报**；多报的后果是**拒绝写入**，不是"越界改坏" —— 刻意的偏向。
  （⚠️ 两者**必须同口径**：早期 `ChangedLines` 没剥前缀，插入 2 行会报 4 行，把合法改动误判成越界 —— 已修。）
  **"多报"到底多多少？有账本了**（`tests\DiffQuality.ps1`，12 个场景实测）：纯插入 / 纯删除 / 纯修改 /
  重复行 / 5000 行大文件 / 全文件重写 **全部准确**；唯一多报的是「**插入（或删除）与修改混在一起**」——
  实测**真实改 2 行、报 12 行**。⇒ 用 `-MaxChangedLines` 时，**混合编辑要按真实改动的几倍留余量**；
  或者干脆别在同一个开关里混着做（先插入、再修改，两次写入比一次混合写入更可控）。
- **护栏 ≠ 牢笼**：调用方完全可以绕开库自己 `WriteAllText`。库管的是"**你用了它，就按规矩来**"。
- **TOCTOU 没被"解决"，但两个口子都堵上了**：① 写**之前**复核哈希 ⇒ 不覆盖别人的改动（`Refused`）；
  ② 回滚**之前**核对"现在这份是不是我写的" ⇒ 别人改过就 `RollbackRefused`，**不拿旧备份去盖**。
  ⚠️ 剩下的边界：**写入完成到回滚开始之间**那个极短的竞争窗口无法消除（要彻底只能上文件锁，见 G 项）。
- **多文件事务的边界**：回滚凭据是**本次提交前**的字节（**不是**演练阶段那份快照）；
  ⚠️ 它只保证"**可处理失败时的整批回退**" —— 进程被杀 / 断电 / 回滚本身失败时**没有**崩溃恢复协议（本库不做）。
  批处理期间**别让别的进程**动这些文件；真动了，`DriftedPlans` 会告诉你，而且回滚仍**不会**覆盖第三方内容。
- **编码**：默认 UTF-8（有无 BOM 都原样保留）；其它编码用 `-Encoding gb2312` 这类名字显式指定；
  检测到 **UTF-16 BOM 直接拒绝**（不猜）。
- **备份会越攒越多，清理必须"演练优先、保底留一份"**：`Prune-Backups.ps1` 默认**只打印清单**，
  加 `-Commit` 才真删；而且**每个目标文件至少保留 1 份**（`-KeepLatest 0` 也按 1 算）——
  唯一能恢复的那份不会因为"超龄"被删掉。只删「又超龄、又不在最新 N 份」的。
  三条不变量有反向验证：`tests\BackupRetention.ps1`（演练不删 / 保底留一份 / 年轻人不动）。
  ⚠️ 它**不检查审计日志引用了哪些备份**：清理会让老记录的 `backup` 字段指向失效路径 ——
  要长期追溯就把 `-OlderThanDays` 设得比追溯期更久。
- **并发写：锁是可选的**（`-Lock`，默认关）。开了以后 Commit 会在目标旁建 `<目标>.wglock` 独占锁
  （`FileShare.None`），挡住"另一个进程正在写同一文件"（第二个 `Refused`），写完必删。
  ⚠️ 进程被强杀可能残留锁文件 —— 下次写入会在 **120 秒**后判定"陈旧"并接管，也可以手动删掉那个 `.wglock`。
  **默认关的理由**：加锁多一次文件操作、残留锁会挡路，这两条代价不该强加给所有调用方（尤其单线程脚本）。
  **★ 平台差异（2026-10-17 实测，别一视同仁）**：
  - **Windows**：操作系统层面就挡住删除。别人持锁时 `File.Delete` **必失败** —— 三组实验（正常持锁 /
    把 mtime 改到 5 分钟前 / 再开第二个独占句柄）全部抛 `MethodInvocationException`。
    ⇒ 120 秒"陈旧接管"在 Windows 上**不会误抢活锁**，最多抢到"没人在持有的残留文件"。
  - **Linux / macOS**：允许删除仍被打开的文件。若 A 真卡住超过 120 秒，B 会删锁并建同名新锁，
    而 A 还握着旧 inode ⇒ **两个进程都认为自己持锁**。这条路径**没有在真机上验证过**（本机只有 Windows）。
  - ⇒ 结论：**Windows 上可以放心用；Unix 上把它当"尽力而为"，别当互斥保证**。
- **"大小写敏感"≠"操作系统类型"**（外部审计 2026-10-17 指出）：本库默认 **Windows ⇒ 不敏感、其它 ⇒ 敏感**，
  但这是**平台策略假设**，不是普遍保证 —— macOS 可以用大小写不敏感的文件系统，
  Windows 也有大小写敏感的目录（per-directory case sensitivity）。
  ⇒ 知道自己在特殊文件系统上时，用 `Invoke-WgBatch -CaseInsensitive $true/$false` 显式覆盖默认；
  单文件路径的来源 hash 用默认策略（它标识的是"这台机器内的同一个文件"，跟文件系统语义一致才对）。
  ⚠️ 另一个坑（同一轮审计抓到的）：**PowerShell 的 `@{}` 默认不区分大小写** ——
  只把路径归一化、却拿默认哈希表装键，敏感策略下仍会把两个不同的键当成同一个。
  所以重复检测用的是**显式比较器的字典**（`Dictionary[string,bool]` + `Ordinal` / `OrdinalIgnoreCase`）。
- **需要 PowerShell 7+**（本机实测 7.6.6）。Windows PowerShell 5.1 未验证 —— 那边读脚本需要 BOM。

## 6.5 和现成方案比，它多什么、少什么

**先说结论**：如果你只需要"改文件前问一句"，用 PowerShell 原生的就够；
WriteGuard 的价值在 **③ 唯一性 · ④ 读回复验 · ⑤ 回滚可分辨**，以及**元验证**。

| 现成做法 | 它管什么 | 差在哪 |
|---|---|---|
| PowerShell 原生 `SupportsShouldProcess` + `-WhatIf` / `-Confirm`（还有 `ConfirmImpact` 分级） | **规矩① 默认不开** —— 这是官方机制，值得用 | 只管"要不要做"，不管备份 / 唯一性 / 读回复验 / 回滚 |
| .NET `File.Replace(src, dst, backup)` | 原子替换 + 留一份备份（**规矩② 的一半**） | 要求目标已存在、只有一次替换；没有"改完读回断言"，也没有失败回滚 |
| 版本控制（git 等） | 事后可回退（**规矩⑤ 的另一条路**） | 回退靠"人记得去回退"，不是机器自动回退；也管不了"只改白名单" |
| 通用测试框架（Pester 等） | 测你的**函数**对不对 | 不回答"我的**检查器**会不会报红"—— 那需要**注入**（本库的 `FaultInject.ps1`） |
| 社区各种"原子写 / 事务式"脚本 | 各自解决"别改坏" | 通常与具体场景耦合；本库把它抽成**五条规矩 + 一套状态机**，且**默认只动副本** |
| 平台自带层（如果你在 **DSH** 这类 harness 里，包自述即证据） | `dsh-fs-observation-policy` 已有 **read-before-edit + version-guarded write/edit**；`dsh-workspace-changes` 已有**每轮改动的 git 快照记录** | 与具体平台绑定；不做"**唯一匹配才改**"、不给"**按备份字节回滚**"，也没有**元验证**（"检查通过 ≠ 检查有效"） |

**⚠️ 最接近的同类：AgentSafeFS（2026-10-17 实测核验，不是照抄它的自述）**

它比本库**走得更远**，这一点如实写出来 —— 只挑对自己有利的维度比，是自欺：

| 维度 | AgentSafeFS | WriteGuard |
|---|---|---|
| 路径安全（`..` / 绝对路径 / symlink·junction / hardlink / NTFS ADS / 8.3 短名 / 保留设备名 / 尾点空格 / 大小写变体绕过） | **全套** | **不做**（本库不是沙箱，也不打算是） |
| 回滚前核对（不覆盖更新的第三方数据） | 有 | **v0.1.2 起有**（我们此前落后这一块） |
| 跨文件原子事务 | **SCOPE 明确不做**（只做单文件写入） | `Invoke-WgBatch`（全成或全退） |
| **元验证**（证明"测试本身有效"） | 无 —— 只列了测试覆盖范围 | M1–M10 + 噪声场景 |
| 回滚能否跨调用 / 跨进程 | ❌ 元数据在内存里，"requires the same instance"；**CLI 明确不提供** | 持有快照即可还原 |
| fsync / 审批绑定 | 有 / `--approve <path>` **精确绑定目标** | 无 / `-Commit` 开关（较松） |
| 工程化 | npm 包 · 六平台原生二进制 · SBOM · 构建溯源 · 签名申请 · THREAT_MODEL / SECURITY / PRIVACY | 单文件 + zip |
| 生态 | Node.js 22+ / MCP | **PowerShell 7+，单文件零依赖** |

**但同一时间实测的"用户面"是另一回事**（2026-10-17 抓 GitHub API）：
它 **0 star · 0 fork · 6 个未解决 issue · 最后推送 2026-09-14**；另一个同类 `patchgate` **1 star · 最后推送 2026-03-12（七个月未动）**。

⇒ 所以结论不是"我们被比下去"，而是：**这个品类拿到用户极难** —— 做到那个工程完整度，也仍然是 0 star。
本库的定位因此是「**先自己用 + 方法论可参考**」；**不把"功能更全"当胜负手**（那一栏追不平，也不必追）。

**多出来的四样**（它值得存在的原因）：
1. **唯一匹配才改**：0 处或多处匹配直接拒绝（"不猜"），再用 `-MaxChangedLines` 兜改动面；
2. **读回磁盘复验**：写完重新读盘、比对文本与 BOM/换行，再跑调用方的断言 —— **断言抛异常也算失败**；
3. **回滚失败单独报**：`RolledBack` 与 `RollbackFailed` 分开，绝不把"没兜住"说成"兜住了"；
4. **元验证**：给自测本身注入故障（每个注入场景都必须被抓到，外加 1 个噪声场景确认尺子不过敏）⇒ 兑现"**检查通过 ≠ 检查有效**"。

**它不做的**（别指望）：不是沙箱规避工具 · 不处理二进制 · **不消除 TOCTOU**（写前与回滚前那两道哈希核对只是**缩小**窗口）· 不做版本控制与并发写协调（需要就配 git / 锁）。
